# M3d community lifecycle baseline review

Window: 2026-08-17 through 2026-09-06

## Purpose

This review validates the first retained issue / pull-request lifecycle dataset and records the main interpretation boundary for later traffic and community analysis.

Lifecycle counts are repository-scoped GitHub events. They are not user counts and they do not by themselves distinguish first-party from external participation.

## Validation result

The automated workflow completed successfully and generated `analytics/community_lifecycle_daily.csv` for all six official OrbitFabric repositories across the rolling 21-day recollection window.

The retained signals are:

```text
issues_opened
issues_closed
prs_opened
prs_merged
prs_closed_unmerged
```

Open and close / merge events are counted independently from GitHub lifecycle evidence rather than inferred from stock deltas.

## Notable activity

The lifecycle baseline makes the early-September development burst visible in a way that stock snapshots cannot.

### 2026-09-02

Core recorded:

```text
prs_opened            10
prs_merged              5
prs_closed_unmerged     5
```

OpenOBSW / OpenSVF recorded one PR open event.

This is a high-churn engineering day and should be treated as development context when reading the same-day clone spike. The lifecycle evidence does not identify who opened the pull requests, so it is not external-community evidence by itself.

### 2026-09-03

The adapter repositories recorded concentrated pull-request activity:

```text
F´ Adapter              7 opened / 7 merged / 1 closed unmerged
OpenC3 / COSMOS         6 opened / 6 merged
OpenOBSW / OpenSVF      8 opened / 9 merged
```

The fact that OpenOBSW has more merges than openings on that UTC day is valid: a pull request opened on an earlier day can merge on 2026-09-03.

Combined with the M3c development dataset, this reinforces the interpretation that 2026-09-03 was an unusually intense ecosystem engineering day. It does not prove that this activity caused clone traffic.

### 2026-09-04

Core recorded:

```text
5 PRs opened
5 PRs merged
```

F´ Adapter recorded:

```text
7 PRs opened
7 PRs merged
```

This is the same day as the F´ releases and upstream discussion already retained in the event registry. The correct interpretation remains mixed evidence: substantial first-party engineering/release activity coexists with public exposure and non-zero browsing traffic.

### Earlier issue lifecycle evidence

The baseline also demonstrates why lifecycle events are useful beyond stock deltas. For example, Core records 7 issue-open events on 2026-08-26 and 10 issue-close events on 2026-08-28. A daily open-issue stock alone cannot reconstruct that flow reliably.

## Interpretation boundary

M3d supports statements such as:

```text
A high-traffic day coincided with substantial PR lifecycle activity.
```

It does not support statements such as:

```text
Those PRs were opened by external contributors.
Those PRs caused the traffic increase.
```

Actor / participation semantics remain a separate M3 increment.

## Result

M3d is validated end to end. The dataset is suitable for later dashboard cross-reading with traffic, stock community signals, development context and curated events.
