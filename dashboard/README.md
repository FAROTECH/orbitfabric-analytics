# Dashboard

Static presentation layer for OrbitFabric Analytics.

## Language style

The dashboard intentionally uses an Italian technical style with familiar English software/analytics terms. Labels such as `Overview`, `Coverage`, `Repository comparison`, `Signal shape`, `Clone activity`, `View activity` and `Ecosystem context` remain in English where that is the natural engineering vocabulary. Explanatory text is in Italian.

## Runtime model

The dashboard is a static PWA. It has no application backend and never calls GitHub APIs from the browser.

Its only analytics input is:

```text
data/dashboard_data.json
```

That file is generated by trusted automation from retained analytics datasets and injected into the deployable site. It is deliberately not committed to `main`.

The payload presents multiple evidence families while preserving their semantics:

```text
TRAFFIC
clone / view activity

COMMUNITY STOCK
stars / forks / open issues / open pull requests / repository-scoped contributor records

LIFECYCLE
issue and pull-request open / close / merge events

PARTICIPATION
repository-scoped aggregate actor-bearing activity

DEVELOPMENT CONTEXT
commits / workflow runs

CURATED CONTEXT
releases / outreach / upstream discussions / community contributions
```

Community stock can be newer than the latest complete traffic day. Lifecycle, participation and development context shown in the dashboard are aggregated over the same common window used by the traffic repository comparison.

## Source files

```text
index.html
styles.css
deltas.css
events.css
context.css
app.js
events.js
event-overlay.js
context.js
manifest.webmanifest
sw.js
data/.gitignore
```

Charts are rendered with Chart.js. Metric meaning is not implemented in JavaScript; the frontend only presents data produced by the analytics layer.

Participation actor logins are not retained or copied into the deployable dashboard. Only aggregate evidence enters `dashboard_data.json`.

## Local preview

Local preview is optional and intended only for development. Copy a generated `dashboard_data.json` into `dashboard/data/`, then serve the directory through any static HTTP server.

## Deployment target

The current deployment path is:

```text
public main
    dashboard source

+ public github-repo-stats
    generated public-safe dashboard_data.json

        ↓ GitHub Actions

dashboard-site
        ↓ Cloudflare Pages Git integration

public-unlisted static PWA
```

The Pages URL is technically public but intentionally unlisted. `noindex`, `robots.txt` and response headers reduce discoverability but are not treated as authentication or confidentiality controls.

Cloudflare Access remains an optional future hardening step if the dashboard ever needs to contain information that should not be publicly accessible.
